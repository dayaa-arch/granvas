# ADR-0001: Semantic node drag without coordinate persistence

- Status: Accepted
- Date: 2026-08-11
- Related: `docs/GRANVAS_SPEC_v0.1.md` §1.2 / §2.3 / §4.7 / §5.4、[ADR-0002](0002-source-edit-plan-as-notation-domain-concern.md)
- Phase: Phase 12 Graph Authoring

## Context

v0.1 の Graph は read-only projection であり、Node drag は無効化されている（§5.4）。しかし「グラフ上のノードを掴んで動かしたい」は、図として構造を見ているとき最も自然に出てくる操作要求である。

一方で Granvas の中核原則は次の2つで、どちらもドラッグと正面から衝突する。

- §1.2 **Text is the source of truth. Graph is a live projection of thought.** グラフの座標・見た目は正本ではない。
- §2.3 記法は「意味と関係を書く言語」であり、`x: 120` / `y: 300` のような見た目の記述を導入しない。

ドラッグを実装するにあたり、「動かした位置をどう扱うか」を決めなければ、この2つの原則のどちらかが暗黙に壊れる。

## Decision

**ドラッグを「配置の操作」ではなく「意味の操作」として定義する。座標は一切永続化しない。**

ノードをドロップした位置は保存せず、ドロップ先が何であったかだけを意味の変更として解釈し、その結果をテキストの書き換えとして反映する。

| ドロップ先 | 解釈される意味 | テキストへの反映 |
| --- | --- | --- |
| 別 Node の上 | その Node を親にする | 行を新しい親の直下へ移動し、indent を `親 indent + 2` に再計算する。トップレベル宣言だった場合は `-> ` を前置する |
| Group overlay の内側 | その Group のメンバーにする | `@id` が無ければ自動採番して宣言行へ付与し、Group ブロックへ `  @id` 行を追加する |
| 空白 | 親子関係を解除する | `-> ` を剥がし、indent 0 の宣言行へ戻す |

付随する規則:

- 自分の子孫を親にする操作（循環）は拒否し、理由を UI に示す。テキストは変更しない。
- Group への drop は既定で「追加」とする。§4.6 が同一 Node の複数 Group 所属を許容しているため、既存の所属を暗黙に剥がさない。
- 兄弟 Node の並び替え（同一親の子同士の順序変更）は本 ADR のスコープに含むが、Phase 12-1 の初期実装対象からは外す。
- Node 座標を `.granvas` へ書き出さない。SVG / PNG / PDF の座標は従来どおり自動レイアウトの出力である。

## Consequences

### 得られるもの

- §1.2 と §2.3 を一切改訂せずに「掴んで動かせる」体験が成立する。
- `.granvas` は引き続き source text だけを保持し、同じテキストから常に同じ意味構造と同じ配置が再生成される（§1.2 の決定性）。
- ドラッグが Undo 可能になる。座標移動は undo 対象にしづらいが、テキスト編集は CodeMirror の history がそのまま担う（[ADR-0002](0002-source-edit-plan-as-notation-domain-concern.md)）。
- レイアウトの決定性テストと export の契約テストが現状のまま維持できる。

### 引き受けるコスト

- **ドロップした瞬間、ノードは指を離した位置ではなく自動レイアウトが決めた位置へ移動する。** これは仕様どおりの挙動だが、何も手当てをしないとユーザーには「掴んで動かしたのに戻った」と読まれる。ドラッグ中にドロップ先の親候補をハイライトし、確定後は新しい配置へアニメーション遷移させることを実装要件とする。この演出は付加的な装飾ではなく、決定を成立させるための必須要素である。
- 「見た目を微調整したい」という要求には応えられない。これは意図的な非対応であり、必要になった場合は本 ADR を supersede する新しい ADR で判断する。
- ドロップ先の判定（ヒットテスト）が意味の分岐そのものになるため、React Flow の座標系と Group overlay bounds を用いた判定ロジックの正確さが体験を直接左右する。

### 仕様への影響

- §5.4 Graph Editing を「read-only projection」から「意味編集は可、座標保存は不可」へ改訂する。
- §2.2 の非対象から「グラフ上からのノード・エッジ編集」を削除する。
- §2.2 の「ノード位置の永続化」「ノード色・形・サイズ・座標を指定する記法」は**非対象のまま維持する**。
- §24 Deferred Decisions の「Node drag の永続化」は引き続き実装しない項目として残す。

## Alternatives Considered

### 案A: 自由配置し、座標を `.granvas` に保存する

draw.io と同じ体験。表現力は最大になるが、§1.2 と §2.3 の改訂が必要になる。より本質的な問題として、座標を保存した瞬間に `.granvas` は「テキスト」ではなく「テキスト＋レイアウト状態」になり、テキストを手で編集したときに座標が意味と食い違う（ノードを削除したのに座標が残る、順序を変えたのに配置が古い）という不整合を恒久的に抱え込む。Granvas が Mermaid 系と差別化している「テキストだけが正本」が失われるため採用しない。

### 案B: ドラッグできるが保存されない（一時的な見た目調整のみ）

実装は最も軽い。しかしテキストは何も変わらず、次の再レイアウトで元に戻るだけなので、ユーザーが得るものがほぼ無い。「動かせるのに意味がない」操作は、動かせないことより体験として悪い。

### 案C: 意味ドラッグ ＋ 手動で動かしたノードだけ位置ヒントを保存する

案A と本決定の中間。表現力は高いが、「自動配置されたノード」と「固定されたノード」が混在するため、レイアウトの決定性テストと export の契約が複雑になる。また、どのノードが固定されているかをユーザーが把握できないと、テキストを編集したときの挙動が予測不能になる。v0.1 の段階で引き受ける複雑さではないと判断した。将来必要になれば本 ADR を supersede する。
